# Orca Cube implementation plan

> Execute inline using superpowers:executing-plans; request final code review.

**Goal:** Install and run Orca on Cube with real machine resources.

**Architecture:** Preserve upstream web client and Node runtime. Add a narrow
loopback gateway and launcher for Cube's authenticated app entry point.

**Tech stack:** Node 24, pnpm, upstream orcad, React/Vite, Cube manifest.

**Spec:** `docs/superpowers/specs/2026-10-11-cube-app-design.md`

## Constraints and review focus

Keep upstream protocol and licenses; isolate test state; protect credentials;
never stop processes owned by other apps or real sessions. Validate pairing
on reload/restart, forwarded HTTPS origins, failed startup, static containment,
and duplex terminal traffic. Keep build memory bounded on shared machines.

## Tasks

- [ ] Build the upstream runtime and web client with pinned tools. Record any
  baseline build failures; add reproducible `cube/install.mjs` and `cube.json`.
- [ ] Add failing gateway tests for static serving, pairing bootstrap, origins,
  traversal, and WebSocket relay. Implement `cube/server.mjs`; verify and commit.
- [ ] Implement `cube/start.mjs`: wait for private runtime readiness, retain the
  pairing offer without logging secrets, serve on PORT, own only its child.
  Add tests for readiness parsing and invalid configuration; commit.
- [ ] Run focused upstream tests and isolated browser acceptance: repository,
  worktree, terminal command/output, reload and restart. Add a reusable smoke
  command and Cube CI. Preserve test evidence and document limitations.
- [ ] Review, fix findings, commit, open a fork PR, and merge according to the
  user's established greenfield preference. Verify merge state.
